# Tsunagi プラグイン

Tsunagi は独自の Claude Code プラグイン——**MCP server**、**skill**、**curator agent**、**hook handler** をまとめたバンドル——を同梱しており、Tsunagi の内部ターミナルで起動した Claude Code に自動で読み込ませます。このプラグインが Tsunagi と Claude の緊密な統合を実現している中核です: Claude が Tsunagi のタスク状態を読み書きできるようにし、いつステータスを変更すべきかを Claude に教え、Claude の活動を Tsunagi UI にリアルタイムに流し込みます。

<Screenshot src="/screenshots/mcp-task-create.webp" alt="Claude が Tsunagi MCP を呼び出す" />

## 中身

プラグイン本体は Tsunagi リポジトリの
[`tsunagi-marketplace/`](https://github.com/minimalcorp/tsunagi/tree/main/apps/web/tsunagi-marketplace)
にあり、npm パッケージに同梱されて配布されます。主要な構成要素は 4 つです。

### MCP server

MCP server は Tsunagi のタスク管理を [Model Context Protocol](https://docs.claude.com/en/docs/claude-code/mcp) 経由で Claude が直接呼べるツール群として公開しています。

| ツール                            | 用途                                                            |
| --------------------------------- | --------------------------------------------------------------- |
| `tsunagi_list_repos`              | 登録済みリポジトリを一覧                                        |
| `tsunagi_list_tasks`              | タスクを一覧 (status / owner / repo 等でフィルタ可)             |
| `tsunagi_get_task`                | `id` / `session_id` / `cwd` でタスクを取得                      |
| `tsunagi_create_task`             | 新しいタスクと worktree を作成                                  |
| `tsunagi_update_task`             | タスクの title / description / status / order / effort 等を更新 |
| `tsunagi_delete_task`             | タスクと worktree を削除                                        |
| `tsunagi_ensure_default_worktree` | `.default` worktree をリモートと同期                            |
| `tsunagi_get_tab_todos`           | 指定タブセッションの todo リストを読む                          |

すべてのツールは Tsunagi が起動する任意の Claude セッション内で追加設定なく使えます。「backlog を優先度順に並び替えて」「このタスクを削除して」といった依頼を Claude にするだけで、裏でこれらのツールが呼ばれます。

### Skill: `tsunagi-task`

プラグインには Claude に MCP ツールの正しい使い方を教える **skill** が含まれています——ステータス遷移ルール、現在のタスクの特定方法、ブランチ命名規則、いつ `description` を更新するか等。skill の全文は
[`skills/tsunagi-task/SKILL.md`](https://github.com/minimalcorp/tsunagi/blob/main/apps/web/tsunagi-marketplace/plugins/tsunagi-plugin/skills/tsunagi-task/SKILL.md)
にあります。

あなた自身が skill を読む必要はありません——Claude は Tsunagi のツールを呼ぶ前に自動的にこれを読みます。

### Curator agent: `tsunagi-task-curator`

「backlog を優先度順に並び替えて」「stale なタスクを棚卸しして」のような triage workflow 専用の **サブエージェント** です。重いタスク description の読み込みをサブエージェント自身のコンテキストに閉じ込めることで、メインの会話がコンパクトに保たれます。

完全な agent 定義は
[`agents/tsunagi-task-curator.md`](https://github.com/minimalcorp/tsunagi/blob/main/apps/web/tsunagi-marketplace/plugins/tsunagi-plugin/agents/tsunagi-task-curator.md)
を参照してください。

### Hook handlers

プラグインは Claude Code の [hooks](https://docs.claude.com/en/docs/claude-code/hooks-guide) を subscribe しています——特に `TaskCreate` / `TaskUpdate`、セッション開始/終了、ツール呼び出しのあたり——そしてそれらのイベントを Tsunagi バックエンドに POST します。これが Tsunagi UI のリアルタイムプログレスバー、ステータスインジケーター、ライブターミナル出力を駆動しています。

## Lifecycle

Tsunagi は内部ターミナルを起動するときに、環境変数 [`CLAUDE_CODE_PLUGIN_DIRS`](https://code.claude.com/docs/en/env-vars) へ同梱のプラグインディレクトリを追加します。そのターミナルで起動した Claude Code は、このプラグインをセッション単位で読み込みます (`--plugin-dir` と同じ扱い)。`claude plugin install` を自分で実行する必要はありません。

- Claude Code の設定には何も install しないので、終了時の後始末はありません。crash してもプラグインの登録は残りません
- Tsunagi の外で起動した Claude Code には読み込まれません
- Claude Code **v2.1.280 以降** が必要です。古い場合 Tsunagi は起動時にエラーで終了します (`claude update` で更新してください)

<Callout type="info">
  旧バージョンの Tsunagi は `claude plugin install --scope user` でプラグインを install
  していました。新しいバージョンの初回起動時に、残っている `tsunagi-plugin@tsunagi-marketplace` と
  `tsunagi-marketplace` を `claude` CLI で1度だけ削除します。
</Callout>

## なぜプラグインはバンドルされているのか

「なぜプラグインを公開 marketplace に publish してユーザーに手動 install させないのか?」と思うかもしれません。答えはバージョン安全性です。Tsunagi のバックエンドとプラグインの MCP ツールスキーマは正確に一致している必要があります。プラグインを Tsunagi の npm パッケージに同梱し、実行中の Tsunagi のディレクトリから読み込ませることで、古いプラグインによるスキーマの不整合が発生する心配がなくなります。
